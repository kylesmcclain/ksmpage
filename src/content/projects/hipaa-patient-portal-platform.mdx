## Scope

"Own the cloud platform" is a broad brief. In practice it decomposed into five things that each
had to be true simultaneously.

**A repeatable path to production.** CI/CD was built and maintained through GitLab so that
application changes deployed the same way every time. Regulated environments punish snowflake
deployments harder than most — if you cannot say how code reached production, you cannot evidence
change control.

**A defined network edge.** Cloud networking, DNS, and load balancing were configured with
Cloud Armor WAF policies in front, so that the portal had an actual perimeter rather than an
implicit one.

**Least-privilege identity.** IAM policies were administered on least-privilege lines. In a PHI
context the access model is the compliance story, and permissive defaults are the single most
common finding.

**A compute and data layer with a recovery story.** Workloads ran across Compute Engine VMs and
Cloud Run containers, with SQL backup policies established for the data tier — a backup you have
tested being the difference between an incident and a catastrophe.

**Real production support.** API and database failure modes were troubleshot directly with the
developers rather than bounced back as tickets. Infrastructure and application problems present
identically at 2am; someone has to be willing to look at both.

## Result

A production healthcare platform with managed deployment, edge protection, controlled identity
boundaries, and a genuine backup posture — operated as infrastructure rather than as a collection
of consoles somebody occasionally logs into.
